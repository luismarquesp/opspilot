# Implementation Plan: Semantic Memory Store & Context Recall

**Branch**: `008-semantic-memory` | **Date**: 2026-09-30 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/008-semantic-memory/spec.md`

## Summary

Add user-scoped semantic memory to OpsPilot via a `MemoryStore` backed by SQLite (`node:sqlite` / `DatabaseSync`) and local dense vector embeddings generated by `@huggingface/transformers` (`all-MiniLM-L6-v2`). The store supports `remember` (with automatic deduplication for cosine similarity > 0.92), `recall` (top-3 results via dot product for similarity $\ge 0.3$), and `forget` (deletion by ID). The HTTP chat endpoint (`POST /chat`) is extended with an optional `userId` parameter, which triggers memory recall and injects relevant operational facts directly into the agent's context.

## Technical Context

**Language/Version**: Node.js 22 LTS, TypeScript ESM, `strict: true`

**Primary Dependencies**: Express 5, Zod, `@langchain/core`, `@langchain/langgraph`, `@langchain/openai`, `@huggingface/transformers`

**Storage**: SQLite via `node:sqlite` (`DatabaseSync`) using binary `BLOB` column for 384-dimensional `Float32Array` vectors; path from `OPSPILOT_DB` (default `./data/opspilot.db`), `":memory:"` in tests

**Testing**: `node:test` via `tsx`, `supertest` for HTTP integration tests

**Target Platform**: Node.js 22 server (single process, local ONNX Runtime CPU inference)

**Project Type**: Web service (Express 5 REST API) + Agent reasoning engine

**Performance Goals**:
- Local embedding generation < 50ms per sentence
- In-memory dot product ranking < 5ms for up to 500 stored memories
- Total `/chat` memory recall overhead < 60ms

**Constraints**:
- Fully offline / local embedding inference (no external API calls or OpenAI token costs for embeddings)
- Lazy singleton model initialization to prevent startup delays
- Strict `userId` isolation across all memory queries and mutations
- Unit-normalized vectors so dot product equals cosine similarity without division

**Scale/Scope**:
- Multi-user support with per-user partitioning
- Typically 5 to 100 operational facts per operator
